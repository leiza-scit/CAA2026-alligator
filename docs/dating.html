Dating machine

Enter how many sherds of each Arretine service type an assemblage holds. The page works out how probable each of the five chronological horizons is, shows why, places the horizons on the year axis, and gives the result as an RDF graph that can be merged with the knowledge graph of this site. Everything is computed in your browser; nothing is sent anywhere.

1. The assemblage

The address of this page carries the counts (dating.html#0,0,13,27,60), so an assemblage can be shared as a link.

2. The attribution

Dirichlet-multinomial predictive likelihood: the pooled sherd counts of each horizon, plus the pseudocount, are the Dirichlet parameters; the five horizons have equal priors. The two pseudocounts differ by less than one percentage point for typical assemblages.

3. Why: the profile of the assemblage

Each horizon has a typical mix of service types. The dashed line is the assemblage; the horizon whose line it follows most closely is the one the model favours.

assemblage (diamonds)coloured lines: reference profile of each horizon, the most probable one drawn heavier

The same as a table, and the reference counts

4. When: the horizons on the year axis

The horizons are those of the knowledge graph on the overview, with the years given there. They overlap, so the bars are not alternatives that add up: the shading shows each horizon's probability (the outline is always drawn), the figure at the right is the same number as above.

5. The result as a graph

The same result as RDF triples. The assemblage is a blank node: it has no identifier of its own. It was present at one deposition event, and each result is a CIDOC-CRM attribute assignment (E13) that says this event falls within one horizon (lado:ChronologicalHorizon, crm:E4_Period) with a probability. The simple view shows that shape; the full view shows every triple of the Turtle below, including where the numbers came from.
